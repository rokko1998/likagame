# Маяк-7 — ассеты первых четырёх экранов

Набор собран по четырём первым PNG из `шаблоны сцен`. **82 итоговых PNG: 4 цельных непрозрачных фона и 78 отдельных файлов с настоящим альфа-каналом.** В каждой сцене статичная обстановка находится в одном фоне. Сверху размещаются самостоятельные объекты, персонажи, эффекты и интерфейс.

## Просмотр и файлы

- `review/index.html` — общий просмотрщик четырёх сцен: отключение слоёв, просмотр отдельного PNG, светлая/тёмная подложка, исходное превью для сравнения, движение, точки крепления и сгиб рук Пика.
- `01-menu` — фон, антенна, два полотнища, корпус/голова ребёнка, корпус/хвост кота.
- `02-map` — фон со всей кабиной, три комнаты-узла карты, флаг.
- `03-approach` — фон со станцией и небом, корпус корабля, радар, пламя. Один PNG пламени используется двумя двигателями.
- `04-dispatch` — фон комнаты, одна зарядная ячейка и одна энергокапсула для повторного использования, разобранный Пик.
- `shared` — **52 PNG** интерфейса и эффектов: логотип, кнопки и состояния, подписи, пиктограммы, карточки карты, сигнал, экраны мониторов, цифры, свечение и декоративные надписи. В `shared/source` сохранены редактируемые SVG-исходники; в игру передаются PNG.
- `review/alpha-report.json` и `asset-index.json` — проверка настоящей прозрачности и точный перечень итоговых файлов.

Запуск просмотрщика из корня проекта:

```sh
python3 -m http.server 4187 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:4187/assets/scene-kit-v1/review/`. Сам `index.html` также можно открыть локально; сохранение сборки через Canvas надёжнее работает через HTTP. Просмотрщик выполняется локально, никуда не отправляет изображения. Это каталог ассетов и проверка сборки, игровая логика приложения в него не переносилась.

## Сборка и анимация

В `manifest.json` каждой сцены заданы координаты на холсте **1672 × 941**, порядок `z`, нормализованная точка вращения `pivot` и назначение движения. `x/y/width/height` описывают **весь PNG**, включая прозрачные поля. Положительный `rotation` — по часовой стрелке в экранных координатах.

У первой сцены флаг имеет базовый поворот `5°`: он совмещает ткань с древком в фоне. У третьей сцены корпус корабля и оба двигателя входят в общий `ship-rig`; движение корпуса должно передаваться обоим языкам пламени.

Пик подключается через `04-dispatch/pik-rig.json`. Риг содержит корпус, заднюю опору, голову, антенну, глаз и **по три части каждой руки: плечевую часть → предплечье → кисть**. Дочерние `position` заданы относительно точки крепления родителя в пикселях сцены. Размеры PNG задаются `width/height`, `pivot` нормализован к изображению. Все части наследуют движение корпуса; глаз и антенна — движение головы. `brightness` задаёт освещение Пика в тёмной комнате, мастер-PNG сохраняют свои исходные цвета.

Точные разрезы рук, исходные координаты суставов, crop и родители сохранены в `04-dispatch/rig/rig-arms.json`. Перекрытие — 112 пикселей исходного рисунка. Нейтральная сборка совпадает с цельными руками пиксельно по видимому RGB и альфе; обе ошибки равны 0. Проверены сгибы до ±20°. На большом увеличении при крайних углах видны мягкие стыки; для спокойной анимации подходят ±8–12°. Это 2D-риг в ракурсе превью: сильные развороты и новые ракурсы требуют дорисовки скрытых поверхностей.

## Удаление нарисованной шахматки кодом

Готовый инструмент: **`tools/matte_checker.py`**. Работает локально на Pillow и NumPy; модели, сеть и платные API не используются.

```sh
python3 assets/scene-kit-v1/tools/matte_checker.py \
  input.png output.png \
  --preview check-light-dark.png
```

Скрипт удаляет светлую нейтральную подложку, связанную с краями изображения, формирует альфу, очищает светлую кайму и мелкие отдельные точки. Светлые детали внутри предмета сохраняются. Уже существующий настоящий альфа-канал по умолчанию копируется без изменения файла. Исходник никогда не перезаписывается.

Для замкнутого отверстия с подложкой: `--seed 420,330` (координаты пикселя внутри отверстия). Параметр можно повторять. Для сохранения светлой детали, касающейся фона: `--keep 100,120,80,50` — прямоугольник `x,y,width,height`. Порог светлоты задаёт `--floor` (по умолчанию 210), допустимую разницу RGB — `--chroma` (32). `--min-area 64` удаляет крошечные отдельные точки. `--force` заменяет только выходной файл.

Это управляемая маска для белого/светло-серого фона, включая запечённую шахматку; она не обещает автоматически отделить любой объект от произвольного пейзажа. Прозрачные стёкла, дым, сильно окрашенная подложка и свечение требуют отдельной маски. Для пламени использован отдельный цветовой алгоритм в `03-approach/finalize_assets.py`.

На капсуле, хвосте и левом флаге постобработка уже применена. Файлы `*.matte.json` фиксируют пороги, дополнительные точки и происхождение. Изображения с запечённой шахматкой могут встречаться только среди явно отмеченных `_source`, не в итоговом перечне и не в сценах.

## Воспроизведение и проверка

```sh
python3 assets/scene-kit-v1/tools/test_matte_checker.py
python3 assets/scene-kit-v1/04-dispatch/rig/build-arms.py
node assets/scene-kit-v1/tools/build_ui.mjs
python3 assets/scene-kit-v1/tools/assemble_kit.py
python3 assets/scene-kit-v1/tools/build_review_data.py
python3 assets/scene-kit-v1/tools/validate_assets.py
```

Для UI-экспорта используются установленный Chrome и Playwright проекта. Для растровой постобработки — `python3`, Pillow, NumPy. Проверка требует PNG, видимую область, полностью прозрачные пиксели у каждого отдельного объекта и ровно один фон на сцену. Она дополнена просмотром на светлой/тёмной подложке и проверкой движений.

Растровые объекты и фоны получены **встроенным `image_gen`**, затем проверены и, где потребовалось, обработаны локальным кодом по запросу пользователя. Точные выполненные промпты находятся в `01-menu/prompts.json`, `02-map/prompts.json`, `03-approach/prompts.json`, `04-dispatch/prompts.json` и `04-dispatch/prompts-alpha-retry.json`; выбранные генерации указаны в `source-index.json` каждой сцены. Интерфейс и простые эффекты построены кодом, их исходники сохранены рядом.

Набор сохраняет композицию и стиль превью. Поскольку исходники — плоские иллюстрации, закрытые поверхности объектов восстановлены; это не побитовое извлечение PSD-слоёв. Исходные четыре превью не изменялись.
