# Руки Пика — шестичастный 2D-риг

Обе исходные руки разделены на плечевую часть, предплечье и кисть. Все шесть файлов — PNG RGBA с настоящей прозрачностью. Исходные `pik-arm-near.png` и `pik-arm-far.png` не изменены.

`rig-arms.json` задаёт родителей, точки вращения в исходных пикселях, точки вращения внутри crop, координаты crop, исходный холст 1536×1024 и пределы углов. Порядок наложения: shoulder → forearm → hand. Корень каждой руки крепится к `pik-body`. Положительный угол — по часовой стрелке в экранных координатах.

При нулевых углах нужно разместить каждый PNG в `sourceCrop.x/y`. Сборка совпадает с исходником **пиксель в пиксель по alpha и видимым RGB**; проверка `qa-report.json` даёт нулевую ошибку для обеих рук. RGB полностью прозрачных пикселей не учитываются.

Вокруг локтя и запястья оставлена зона перекрытия 112 px. Альфа частей распределена комплементарно, поэтому область перекрытия в исходной позе не становится темнее или непрозрачнее. При анимации матрица дочерней части наследует матрицу родителя, затем добавляет вращение вокруг своего `pivotSource`. Полный рабочий пример этой математики находится в `render_pose` скрипта.

Проверены нейтральная поза и два противоположных сгиба: локоть +20° / кисть −20° и локоть −20° / кисть +20°. Файлы `qa-near-poses.png` и `qa-far-poses.png` показывают их на тёмном и светлом фоне. На крайних углах при крупном просмотре видны мягкие края разделения у суставов: это ограничение нарезки единственного рисунка без дорисовки скрытых поверхностей. Для фоновой анимации в сцене лучше использовать ±8–12°; для крупного плана с сильным сгибом потребуется отдельная прорисовка суставов. Формальные пределы в JSON оставлены ±20°, соответствующие выполненной проверке.

Воспроизведение:

```sh
python3 assets/scene-kit-v1/04-dispatch/rig/build-arms.py
```

Нужны Pillow и NumPy. Скрипт выполняет только локальную обработку двух указанных исходников и записывает результаты в эту папку. Сценовые manifest и другие папки он не изменяет.
